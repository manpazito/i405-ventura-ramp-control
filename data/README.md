# Data

PeMS District 7 Station 5-Minute archives for October 2022 have been acquired; the files
are git-ignored. The PeMS pipeline (`uv run arm-pems`, [below](#pems-pipeline)) writes
`raw/pems/` (daily District 7 archives, catalog JSON, metadata snapshots),
`interim/pems/` (corridor rows per day, `scan_log.csv`) and `processed/pems/`
(screening, ranking, inventory, SI exports); dataset manifests go to `manifests/`.
What the data show for the site is under [site coverage](#site-coverage-findings-2026-11-13).

| Directory | Purpose |
| --- | --- |
| `raw/` | Original acquired traffic observations, unchanged |
| `external/` | Original third-party geometry, metadata, plans, and supporting material |
| `interim/` | Reproducible intermediate transformations |
| `processed/` | Versioned analysis inputs with an explicit schema and split assignment |

Raw/external files are immutable: never overwrite a download, manually repair a
source table, or hide its missing values. Keep corrections in derived files with
the transformation recorded. Bulk content in all four directories is ignored by
Git; their `.gitkeep` files and this documentation are retained. Commit only small,
permitted fixtures deliberately when future tests require them. Keep `uv.lock` and
dataset manifests in Git; data versioning/storage technology remains undecided.

## Naming and provenance

Use `<origin>_<source>_<site>_<coverage>_<resolution>_v<revision>.<ext>` for derived
data, where origin is `observed`, `synthetic`, or `derived`. Tokens use lowercase
letters, digits, and underscores. `coverage` is a dated range or observation year,
not the download date; `resolution` records such values as `5min` or `geometry`.
Keep source filenames in raw/external storage inside a uniquely named acquisition
directory. Do not invent a station ID or date to fill a filename.

When data is acquired, create a small manifest under `data/manifests/` keyed by
`dataset_id`: source-registry ID, agency, exact URL or request reference, retrieval
time, observation dates, location/direction/lane scope, original filename, byte
size, SHA-256, original schema and units, timezone/interval semantics, license or
permission, quality notes, and responsible contributor. Derived manifests add
parent checksums, transformation/configuration and code versions, schema version,
and calibration/validation assignment. Never include passwords, tokens, or private
request correspondence. Two manifests in `manifests/` record the October 2022 PeMS exports.

## Time and units

- Preserve original timestamp text and metadata. Interpret local times as
  `America/Los_Angeles` only after confirming the source convention. Store normalized
  timezone-aware UTC timestamps and retain the source zone and offset. Ambiguous
  fall-back hours need an offset/fold; nonexistent spring-forward times need a flag,
  not an invented record.
- Use explicit half-open intervals `[start, end)` after establishing whether the
  source labels interval starts or ends. Store simulation time in elapsed seconds
  with a documented origin; civil timestamps require a scenario epoch mapping.
- SI conversions at documented boundaries: mph × 0.44704 → m/s; ft × 0.3048 → m;
  mile × 1609.344 → m; veh/h ÷ 3600 → veh/s; occupancy percent ÷ 100 → fraction.
  Counts stay counts. A count $n$ over $\Delta$ seconds yields $n/\Delta$
  veh/s. AADT is veh/day over its reporting period, not peak-hour demand.
- Keep original unit columns in provenance. Distinguish per-lane totals, all-lane
  totals, time-mean speed, space-mean speed, and estimated speed.

## Missingness, versions, and research splits

Missing/unavailable measurements stay null with a reason; zero means a measured
zero. Preserve agency quality flags and label estimated or imputed values. Any
future imputation must be explicit, reproducible, and fitted using allowed data.

Keep observations, synthetic demand, and model outputs in separate datasets with
origin labels. Derived data must retain whether its parents are observed or
synthetic; simulations are never relabeled as observations. Use new dataset
revisions and checksums for changes, including corrected agency releases.

Choose calibration/development and held-out validation periods before tuning.
Prefer disjoint whole dates or episodes over adjacent random rows. Record the
split manifest and freeze validation until choices are fixed. Geometry, sensor,
or temporal overlap and leakage risks must be disclosed. Forecasting is out of scope
since 2026-11-18 (D020); no forecasting split is prescribed.

## PeMS pipeline

Status 2026-11-07: implemented, unit-tested on synthetic fixtures, and run with a team
PeMS session for stages 1–5 (all 21 October 2022 weekdays plus one October week in
2023, 2024 and 2025). See
[Findings](#findings-2026-11-07) at the end; outputs live under `data/` (git-ignored)
and are regenerated by the commands below.

### Components and reuse

- `pems-data` 0.2.0 (MIT, Chenchen Wei, pinned to commit `a66cdf3` via `uv`), used for
  the documented browser login (`pems-data auth`, Playwright/Chromium, session cookies
  in `.pems/storage-state.json`, mode 600, git-ignored) and the resumable authenticated
  download with expired-session detection. Its own `fetch` is not used: it aborts when any
  requested day is unlisted, deletes raw archives by default, and does no screening.
- `src/adaptive_ramp_metering/data/pems.py` (`uv run arm-pems`): catalog listing cached
  per district/year, staged weekday scan, corridor extraction, per-station-day screening,
  period ranking, SI export with manifest. Settings in `configs/pems.yaml`.

### Commands

```bash
uv sync                                 # installs pems-data, playwright, requests
uv run playwright install chromium      # once
uv run pems-data auth                   # log in interactively; never commit .pems/
uv run arm-pems inventory --date 2022-10-17   # corridor detector inventory
uv run arm-pems scan --stage 1          # 2022-10-17..21; stages 2-5 widen the search
uv run arm-pems scan --dates 2022-10-24 2022-10-25
uv run arm-pems rank                    # candidate_periods.csv / candidate_days.csv
uv run arm-pems export --start 2022-10-17 --end 2022-10-21   # SI dataset + manifest
```

Credentials can be supplied to `pems-data auth` through `PEMS_USERNAME`/`PEMS_PASSWORD`
for the current shell only; nothing in this repo reads or stores them.

### Efficiency and resumability

- Daily archives (`d07_text_station_5min_YYYY_MM_DD.txt.gz`, District-wide, tens of MB)
  are kept in `data/raw/pems/` and reused; partial downloads resume by HTTP Range.
- Catalog JSON per year is cached in `data/raw/pems/catalog/`; use `--refresh-catalog`
  for the current year.
- Days absent from the catalog are logged as `not_listed` in
  `data/interim/pems/scan_log.csv` and skipped on reruns unless `--retry-missing`.
- Transfers are serial (PeMS discourages concurrent automated downloads) with
  configurable retries and exponential backoff; failures are logged, progress kept.
- A day already extracted to `data/interim/pems/station_5min_<date>.csv` is only
  re-screened, not re-downloaded. The extract is written to a `.part` file and renamed
  when complete, so an interrupted run cannot leave a partial day under that name.
- A day whose archive has no rows for the configured stations is stored as failing
  rows (0 records) and ranked as a non-qualifying day.

### Screening method (per station and local day)

Source rows: timestamp (America/Los_Angeles, interval start per PeMS convention),
station, lane type, samples, % observed, total flow (veh/5 min), average occupancy
(fraction), average speed (mph, flow-weighted). Metrics, all in
`data/processed/pems/quality_screening.csv`:

| Metric | Definition |
| --- | --- |
| `expected_intervals` | 5-min slots in the local civil day (288; 276/300 on DST days) |
| `available_records`, `duplicate_timestamps`, `missing_pct` | rows present; `100·(expected−available)/expected` |
| `mean_observed_pct`, `pct_intervals_ge90` | mean of `% Observed`; share of expected intervals with ≥90 % observed (absent intervals count as failing) |
| `flow_reported`, `speed_reported`, `occupancy_reported` | non-null values, whether observed or PeMS-imputed |
| `flow_observed` | non-null flow with `% Observed` > 0 |
| `zero_flow_unobserved` | flow = 0 with 0 % observed: **not** evidence of zero traffic |
| `negative_values`, `occupancy_out_of_range`, `speed_above_max`, `longest_stuck_flow_run` | plausibility counts feeding `suspicious` |
| `meets_thresholds` | `min_mean_observed_pct`, `min_pct_intervals_ge90`, `max_missing_pct` from config |

Thresholds are configuration, not a claim about acceptable quality; set them per
research question before calibration and record the choice in `docs/decisions.md`.

### Ranking

`arm-pems rank` marks a day as qualifying when every `required_roles` station
(default on-ramp and mainline) is present and meets the thresholds, then groups
consecutive weekdays (Friday to Monday counts as consecutive) with the same status and
station set into periods ranked by qualification, length, then minimum coverage.
Incident dates from the config are counted, never dropped. Non-qualifying runs stay in
the table with `missing_required_roles` explaining why.

### Export and provenance

`arm-pems export` writes `data/processed/pems/observed_pems_ventura_<start>_<end>_5min_v<n>.csv`
with `interval_start_utc`/`interval_end_utc` (`[start, end)`, 300 s), `sensor_id`,
`count` (veh), `flow_veh_per_s` = count/300, `mean_speed_mps` = mph × 0.44704,
`occupancy_fraction` (source fraction, unchanged), `observed_fraction`, `quality_flag`
(`observed`, `partially_observed`, `imputed`, `missing`) and the original local
timestamp. The manifest `docs/data/manifests/<dataset_id>.json` records the source
archives with URL, size, SHA-256 and retrieval time, station roles, units, timezone
convention, the config snapshot, code commit, and an `unassigned` split.

### Limitations and open checks

- The occupancy-as-fraction and timestamp-as-interval-start conventions follow the PeMS
  Station 5-Minute documentation and the downloader's smoke test; confirm on the first
  real archive (`occupancy_out_of_range` must be 0).
- Station 5-Minute archives contain the detector-health status only indirectly through
  `% Observed`; the "Line Down" status seen on the website is not in these files.
- Metadata snapshots are dated; the inventory uses the latest snapshot on or before the
  scan date, so lane counts or names may differ from today's website.
- Ramp detector side of the meter (arrival versus release) is not in PeMS metadata.

### Findings (2026-11-07)

Source: District 7 Station 5-Minute archives `d07_text_station_5min_2022_10_03` …
`2022_10_31` (21 weekday files, ~27 MB each, SHA-256 in `data/interim/pems/scan_log.csv`)
and metadata `d07_text_meta_2022_07_15.txt`. Thresholds as in `configs/pems.yaml`
(mean observed ≥ 90 %, ≥ 90 % of intervals at ≥ 90 % observed, ≤ 5 % missing).

- **Identity verified.** Metadata lists 716744 (OR, 1 lane), 717816 (ML, 5 lanes) and
  765197 (FR, 1 lane) at Abs PM 62.862 / CA PM 39.09, name VENTURA, I-405 S. The
  corridor filter (Abs PM 61.5–64.0) yields 18 stations; `detector_inventory.csv`.
- **On-ramp 716744**: 288 records every day, 95.8–100 % observed, passes all 21 days.
  No speed is reported for ramps.
- **Mainline 717816**: passes 9 of 21 days. Failing days sit at ≈ 80 %, 60 % or 58 %
  mean observed with 0 % of intervals ≥ 90 %, consistent with 1–2 of 5 lanes imputed
  all day (lane-level failure, not a communication gap). Not yet checked per lane.
- **Off-ramp 765197**: 0 % observed on all 21 days; values are entirely PeMS-imputed.
- **Qualifying simultaneous periods (on-ramp + 717816)**: Oct 10–12 (3 days),
  Oct 24–25, Oct 14 + Oct 17 (Oct 17 is a team-reported incident day), Oct 3, Oct 28.
  Oct 18–21 (the week first examined) fails on the mainline.
- **Boundary candidates**: upstream mainline 777066 (NORTH OF 101, Abs PM 63.27,
  3 lanes) is ≥ 95.8 % observed every day; 765171 (BURBANK 1) passes most days.
  Downstream mainline is poor: 764754 (WOODCREST) 17–67 %, 717809 (VALLEY VISTA) 0 %.
- **Candidate for checking**: 716744 and 777066 show identical daily mean observed
  percentages on all 21 days, suggesting shared communication rather than independent
  detector health. Treat ramp `% Observed` dips as line outages until explained.

These are coverage facts from PeMS health flags, not validation of the measurements.

## Site coverage findings (2026-11-13)

Coverage facts from PeMS `% Observed` and report metadata. They are not validation of
the measurements. Method and earlier screening: [pipeline findings](#findings-2026-11-07).

**Only October 2022 has observed ramp and mainline data.** Ventura on-ramp 716744 and
mainline 717816 are 0 % observed on every sampled day in October 2023, 2024 and 2025.
The 2024 and 2025 AM (06–10 h) mean flows at 717816 are identical (466 veh/5 min on
Oct 15, 2024 and Oct 14, 2025), which fits imputation. The PeMS change logs
(`data/pdfs_to_scan/`, retrieved 2026-11-13) list both stations as Disabled on
2023-12-19 and Active again on 2023-12-22. "Active" in metadata does not mean the
detector reports.

**The 2026 PeMS web reports in `data/raw/` are not evidence.** The files are
`i405S_2026-10-19--23_{Flow,Occupancy,Speed}.xlsx` (Ramp Analysis, 716744 with 717816)
and `Ventura_Sepulveda_{VMT,Delay}_10_26.xlsx`. Every interval is 0 % ramp- and
mainline-observed, and the ramp flow is 0 throughout. Their mainline occupancy, speed,
VMT and delay values are PeMS estimates. Keep the files in raw as received, but do not
use them for calibration, validation or the motivation figures.

**Open check: ramp detector position.** On 2022-10-18 at 07:30 the 716744 5-minute
occupancy is 0.746 with 59 veh. That fits a standing queue over the loop. PeMS
metadata does not say whether the loop is upstream of the meter (demand or queue) or
downstream (release). Settle this from dated imagery before the ramp count is used as
either arrival demand or a delivered metering rate.

The PeMS "Max Cap." for 717816 (163.4 veh/min, dated 2017-04-01) is a PeMS estimate,
not a measured capacity. Use it only as a plausibility reference.
